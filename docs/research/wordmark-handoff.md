# Intro wordmark handoff and center-out reveal

Checked: 2026-11-07 · Status: answered; visual/device verification required
Scope: research only. Supersedes the earlier intro note's sliding-panel recommendation for this requested revision. No app code, dependencies, commits or deployments.

## Recommendation

**Pata-specific inference:** animate one decorative copy of the large intro “Pata” into the measured bounds of the existing top-left header wordmark. At the same time, erase the forest-green intro surface outward from its center with an expanding cutout. Keep the moving wordmark above that surface so the opening cannot erase it. End by revealing the real header text and removing the decorative copy together. Preserve the existing icon, type, navigation and home layout.

Use original small React/browser code with the Web Animations API for the text, plus one local inline SVG for the surface. No library is necessary. An approximately 650–850 ms coordinated handoff is a starting design recommendation, not a browser or library requirement; tune against the supplied reference. An irregular, restrained edge can suggest dissolution; a smooth expanding ellipse reads as an aperture. Neither is a particle simulation, and neither requires sliding panels.

## Implementation shape and limits

1. Measure the intro text and actual header text with viewport-relative rectangles after layout. Use the same font family, weight, letter spacing and text content. Animate a fixed-position, `aria-hidden`, pointer-transparent text copy with a top-left transform origin. Translate to the target and uniformly scale by the font-size/width ratio. Do not scale X and Y independently: that distorts the serif. Bounding rectangles include line boxes, so verify baseline and ink alignment visually; measure text spans rather than broad button/header wrappers. These are design/implementation recommendations, not features supplied by the libraries.
2. Hide only the real header wordmark visually during the flight; reserve its layout space and preserve its link's accessible name. Avoid two visible wordmarks, character splitting, a replacement logo or a whole-header transform. At completion restore the actual text, remove the flight copy, and discard temporary styles in one guarded finish operation.
3. Render the intro surface as an inline SVG rectangle covered by a **luminance** mask: white viewport rectangle retains green; an expanding black circle/ellipse removes it. Set mask units and bounds explicitly in viewport/user coordinates. For a centered circle, a final radius of at least `hypot(width / 2, height / 2)` reaches every corner. A few restrained irregular contours can create a broken edge, but keep their sampling deterministic. This construction follows the [CSS Masking specification](https://drafts.csswg.org/css-masking-1/#MaskElement): luminance masks use lightness to determine opacity. Black is not a hole in an alpha-only mask when its alpha is opaque.
4. WAAPI suits transform/opacity on the text; do not assume `Element.animate` portably animates SVG `r` attributes. For a changing radius, use a short cancellable requestAnimationFrame loop setting the attribute, or a verified CSS transform on SVG geometry. Coordinate both pieces from one entry state and a common duration. No mask/frame loop should own access to the home indefinitely.
5. Keep this local intro interaction separate from route transitions. Native [same-document View Transitions](https://developer.chrome.com/docs/web-platform/view-transitions/same-document) can move named snapshots between old/new geometry, but require a DOM update inside capture, unique transition names and capability fallback. They add snapshot/global-pseudo-element coordination to a task already solvable with two measured elements; do not add them solely for this handoff.

The masking recommendation uses the normative [CSS Masking source](https://drafts.csswg.org/css-masking-1/); the shared-snapshot alternative was checked against Chrome's first-party guide today. No performance or cross-browser visual claim has been device-tested by this note.

## Completion, accessibility and verification

Treat entry as an idempotent state change: repeated taps cannot start overlapping flights. Ensure cancellation, resize/orientation change, unmount, unavailable APIs or an animation failure all restore the actual header and remove the intro surface. Handle rejected `Animation.finished` promises on cancellation; the [Web Animations specification](https://drafts.csswg.org/web-animations-1/#canceling-an-animation-section) defines that rejection and removal of the animation's effect. Cancel RAF and outstanding animations during cleanup; stale callbacks must not alter a newer state.

Honor [prefers-reduced-motion](https://drafts.csswg.org/mediaqueries-5/#prefers-reduced-motion), checked in the normative source today: skip the flight and expanding hole and complete entry immediately. Observe changes while running and finish immediately if reduction becomes requested. Keep the native entry button keyboard operable, prevent obscured home controls from receiving focus, then place focus at the established meaningful home destination. Decorative geometry and the flying copy must not add announcements. These are Pata-specific accessibility recommendations grounded in the preference's purpose, not automatic library behavior.

Verify at 320px and ordinary phone/laptop sizes, landscape, enlarged text and reduced motion before/during entry. Check exact header baseline handoff without flicker or duplicate text; corner clearance of the reveal; repeated activation; keyboard focus; resize during flight; animation API failure; and successful static export. Retain existing home-only/once-per-session behavior and direct-route bypass. Do not inspect or change courier fragments for animation. Reuse the route-safety constraints from [page transitions](page-transitions.md).

## Implementation choice

The implementation moves the original intro heading (no text snapshot/copy). The user's refinements replace the initial geometric sectors with the recommended single smooth SVG aperture, then anchor that opening to the Enter Pata button: a black unit circle in a luminance mask scales from zero to the farthest viewport corner plus a small clearance. The wordmark still travels from the center to the header; peripheral intro elements leave outward. The real header text stays hidden until completion. Matching Georgia, weight, tracking and line-height allows one uniform scale with no glyph distortion. To preserve contrast with the new bottom-up opening, the ink-color change is centered on when the aperture reaches the moving text, sampled once from native animation easing before playback. No layout reads occur in that sampling loop. No source from either component library was copied.
