### 1. Registering `pata.eth` and `digipin.eth` (hour 0–2)

Contracts: ETHRegistrar `0xf633e7fc17e2bbe0d0965d18ec1821dcb754a3d3`, ETHRegistry `0xd4ebcbbdf463c9c45784603db0ddd499bc44a8b4`, MockUSDC `0x240b0316df57887dbbe58b586508b19e633a14aa` ([deployments](https://docs.ens.domains/learn/deployments#sepolia-ensv2)). Flow from [ETH Registrar](https://docs.ens.domains/ensv2/eth-registrar) and [`ETHRegistrar.sol`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/registrar/ETHRegistrar.sol):

1. `MockUSDC.mint(address to, uint256 amount)`; 6 decimals per the docs example (`100_000_000n` = 100 USDC).
2. `ETHRegistrar.isAvailable(string label) → bool`; `getRegisterPrice(string label, uint64 duration, IERC20 paymentToken) → (uint256 base, uint256 premium)`.
3. `MockUSDC.approve(ETHRegistrar, base + premium)`.
4. `makeCommitment(string label, address owner, bytes32 secret, IRegistry subregistry, address resolver, uint64 duration, bytes32 referrer) → bytes32` (pure: `keccak256(abi.encode(label, owner, secret, subregistry, resolver, duration, referrer))`), then `commit(bytes32)`.
5. Wait at least `MIN_COMMITMENT_AGE` (docs: 60 s) and less than `MAX_COMMITMENT_AGE` (docs: "typically 24 hours").
6. `register(string label, address owner, bytes32 secret, IRegistry subregistry, address resolver, uint64 duration, IERC20 paymentToken, bytes32 referrer) → uint256 tokenId`. The fee goes to `BENEFICIARY` by `safeTransferFrom`; expiry is `block.timestamp + duration`.

- **Price:** $8/yr for 5+ characters, **$160/yr for 4 characters**, $640/yr for 3; multi-year discounts 12.5% (2 yr), ~31% (3–5 yr), ~44% (6 yr) ([ETH Registrar → Pricing](https://docs.ens.domains/ensv2/eth-registrar)). `pata` is 4 characters, so it costs 20× `digipin`; with free MockUSDC that only means minting enough.
- **Roles the owner gets** (fixed, not configurable): `ROLE_SET_SUBREGISTRY`, `ROLE_SET_SUBREGISTRY_ADMIN`, `ROLE_SET_RESOLVER`, `ROLE_SET_RESOLVER_ADMIN`, `ROLE_CAN_TRANSFER_ADMIN` (`REGISTRATION_ROLE_BITMAP` in `ETHRegistrar.sol`). No `ROLE_RENEW`, no `ROLE_UNREGISTER`: anyone renews through the registrar, nobody unregisters.
- **Save a transaction:** `subregistry` and `resolver` are part of the commitment, so deploy `pata.eth`'s registry (flow 2) first and pass it here; otherwise call `ETHRegistry.setSubregistry` afterwards (inferred from the signature).
- **Duration:** must be ≥ `MIN_REGISTER_DURATION` (value **open**, read it on-chain). The docs set no maximum ("There is no maximum registration duration", [FAQ](https://docs.ens.domains/faq)). Because a parent's expiry bounds every name under it (flow 3), register `pata.eth` for several years.
- Sepolia's `MIN_COMMITMENT_AGE`, `MIN_REGISTER_DURATION`, the accepted payment tokens and today's availability of both labels: **open** until the on-chain reads below are added.

### 2. `pata.eth`'s own subname registry

A subname registry is a `UserRegistry` proxy (a `PermissionedRegistry` subclass) deployed through the Verifiable Factory ([Registry Template](https://docs.ens.domains/ensv2/registry-template), [`UserRegistry.sol`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/registry/UserRegistry.sol)).

- **Deploy:** `VerifiableFactory(0xda70306c98e97ece36f997a21368e53298572991).deployProxy(address implementation, uint256 salt, bytes data) → address proxy`, with `implementation = UserRegistryImpl 0x9bd8a88719068d09ecee662f36c0e3856708366a`.
  - `salt`: docs convention `uint256(keccak256(abi.encode(keccak256("UserRegistry"), namehash("pata.eth"), uint256(0))))` ([Verifiable Factory](https://docs.ens.domains/ensv2/verifiable-factory)). The factory mixes in the caller (`outerSalt = keccak256(abi.encode(msg.sender, salt))`), so the convention avoids nothing on-chain; it only makes the address predictable. `predictProxyAddress(address deployer, uint256 salt)` returns the address before deployment ([`VerifiableFactory.sol`](https://github.com/ensdomains/verifiable-factory/blob/c1090aec465ab30d494c96bd7d2a147b4f0b0173/src/VerifiableFactory.sol)).
  - `data`: `initialize((address account, uint256 roleBitmap)[] grants)`. Each grant is applied on `ROOT_RESOURCE`; it reverts `InvalidOwner` if no root role is granted at all.
  - The address comes back in `ProxyDeployed(address indexed sender, address indexed proxyAddress, uint256 salt, address implementation)`.
- **Roles for an emancipated registry** (what makes household names "forever"): the operator (our deployer, or the relay that registers households) gets `ROLE_REGISTRAR | ROLE_REGISTRAR_ADMIN | ROLE_RENEW | ROLE_RENEW_ADMIN` and, if we want the canonical-name pointer, `ROLE_SET_PARENT | ROLE_SET_PARENT_ADMIN` (revoked after `setParent`). It must **not** get any of `UNEMANCIPATED_ROLE_BITMAP` on root: `ROLE_CAN_TRANSFER_ADMIN`, `ROLE_SET_SUBREGISTRY(+_ADMIN)`, `ROLE_SET_RESOLVER(+_ADMIN)`, `ROLE_UNREGISTER(+_ADMIN)`, `ROLE_UPGRADE(+_ADMIN)` ([`RegistryRolesLib.sol`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/registry/libraries/RegistryRolesLib.sol); `isEmancipated()` in [`PermissionedRegistry.sol`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/registry/PermissionedRegistry.sol) is `(UNEMANCIPATED_ROLE_BITMAP & rolesWithAssignees(ROOT)) == 0`). The docs' examples grant `ALL_ROLES = 0x1111…1111`, which is *not* emancipated.
- **Attach:** `ETHRegistry.setSubregistry(uint256 anyId, IRegistry registry)` with `anyId = uint256(labelhash("pata"))`, called by the `pata.eth` owner (holds `ROLE_SET_SUBREGISTRY` from registration), or pass the registry at registration. Until this pointer exists, names in the registry "mint tokens but never resolve" ([For Contract Developers](https://docs.ens.domains/ensv2/tutorial-contract-developers)).
- **Optional canonical parent:** `pataRegistry.setParent(ETHRegistry, "pata")` (root `ROLE_SET_PARENT`), then `revokeRootRoles(ROLE_SET_PARENT | ROLE_SET_PARENT_ADMIN, operator)` to lock it ([Permissioned Registry → Parent Pointer](https://docs.ens.domains/ensv2/permissioned-registry)). `UniversalHelper.findCanonicalName/findCanonicalRegistry` need it; resolution does not.
- **Lock the pointer from above:** while the `pata.eth` owner holds `ROLE_SET_SUBREGISTRY` on `pata` in the ETHRegistry, it can swap the whole subtree out in one call ([Registry Hierarchy → Subtree Operations](https://docs.ens.domains/ensv2/registry-hierarchy)). To make household names untouchable, the owner calls `ETHRegistry.revokeRoles(labelhash("pata"), ROLE_SET_SUBREGISTRY | ROLE_SET_SUBREGISTRY_ADMIN, owner)`; admin holders may revoke their own roles ([Permissioned Registry → EAC Hook Overrides](https://docs.ens.domains/ensv2/permissioned-registry)). This step is inferred from those two docs passages; the docs don't spell it out for 2LDs. It is irreversible.

### 3. Household name `sana.pata.eth`

- **Its own Permissioned Resolver**, deployed by the household key: `deployProxy(PermissionedResolverImpl 0x115eb53f0c60696633855f90b138178fb40b2b2c, salt, data)` with docs salt `uint256(keccak256(abi.encode(keccak256("OwnedResolver"), owner, uint256(version))))` and `data = initialize((address account, uint256 roleBitmap)[] grants, bytes[] calls)` ([Verifiable Factory → Deploying a Resolver Proxy](https://docs.ens.domains/ensv2/verifiable-factory)). Grants land on the resolver's `ROOT_RESOURCE`; `calls` run as a multicall **with role checks skipped**, so the household's first records (locality, encryption key) can be written in the same transaction ([`PermissionedResolver.sol`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/resolver/PermissionedResolver.sol) `initialize` and `_checkRoles` override). A resolver instance is per account, not per name: every name pointed at it shares its roles ([Permissioned Resolver](https://docs.ens.domains/ensv2/permissioned-resolver)).
- **Registration in `pata.eth`'s registry**, by the operator holding root `ROLE_REGISTRAR`: `pataRegistry.register(string label, address owner, IRegistry registry, address resolver, uint256 roleBitmap, uint64 expiry) → uint256 tokenId` with `label = "sana"`, `owner =` household key, `resolver =` the household resolver, `registry =` the household's grant registry if already deployed (else `address(0)` and set later).
  - `roleBitmap` for a forever name: `ROLE_SET_RESOLVER | ROLE_SET_RESOLVER_ADMIN | ROLE_SET_SUBREGISTRY | ROLE_SET_SUBREGISTRY_ADMIN | ROLE_CAN_TRANSFER_ADMIN` (the `.eth` bitmap). Admin roles on a name can only be given at registration, so give them now ([Permissioned Registry → EAC Hook Overrides](https://docs.ens.domains/ensv2/permissioned-registry); `_getSettableRoles` returns `roleBitmap >> 128` for names). `ROLE_CAN_TRANSFER_ADMIN` lets the household move the name to a new key, which is the recovery path if the key changes (inferred).
  - `expiry`: `type(uint64).max` (`18446744073709551615`) makes it non-expiring; `renew` can never reduce an expiry, and nobody can unregister it in an emancipated registry ([For Contract Developers → Next Steps](https://docs.ens.domains/ensv2/tutorial-contract-developers): "for permanent subnames, pass `type(uint64).max` … abandoned names never return to the available pool").
  - Pata's operator then cannot change `sana`'s resolver, subregistry or owner, or delete it, because it holds no dangerous root role; `pataRegistry.isEmancipated()` proves it, after `VerifiableFactory.verifyContract(pataRegistry)` confirms the implementation ("an arbitrary contract can simply always return `true`", [Permissioned Registry → Emancipation](https://docs.ens.domains/ensv2/permissioned-registry)).
  - Remaining dependency: `pata.eth` itself. If it expires, `ETHRegistry.getSubregistry("pata")` returns zero and every household and grant stops resolving ([Universal Resolver V2](https://docs.ens.domains/ensv2/universal-resolver-v2): "if a parent name expires … all subnames stop resolving automatically"). Anyone can renew a `.eth` name through the registrar ([ETH Registrar](https://docs.ens.domains/ensv2/eth-registrar)).
- **The household's own registry for grants:** the household key deploys another `UserRegistry` proxy (`salt` convention with `namehash("sana.pata.eth")`), initialized with root `ROLE_REGISTRAR | ROLE_REGISTRAR_ADMIN | ROLE_UNREGISTER | ROLE_UNREGISTER_ADMIN | ROLE_RENEW | ROLE_RENEW_ADMIN` for itself (or `ALL_ROLES`). Then the household calls `pataRegistry.setSubregistry(labelhash("sana"), householdRegistry)` (it holds `ROLE_SET_SUBREGISTRY` on its token). This registry is deliberately **not** emancipated: root `ROLE_UNREGISTER` is the household's revoke power, and it counts as a dangerous role.
- **Household agent (P2):** `householdRegistry.grantRootRoles(ROLE_REGISTRAR, agent)`: it can issue grants but not revoke or touch records ([Permissioned Registry](https://docs.ens.domains/ensv2/permissioned-registry); [Enhanced Access Control](https://docs.ens.domains/ensv2/enhanced-access-control)). A root role is registry-wide; it can't cap grant lengths (`register` takes any future expiry).

### 4. A grant, e.g. `k3f9x2qa.sana.pata.eth`

- **Issue:** `householdRegistry.register("k3f9x2qa", oneTimeAddress, IRegistry(address(0)), address(0), 0, expiry)`.
  - `roleBitmap = 0`: the requester holds no role on its token, so it can't set a resolver or subregistry, renew, unregister, or transfer. A transfer checks `ROLE_CAN_TRANSFER_ADMIN` on the *owner's* token-level roles and reverts `TransferDisallowed` without it; root roles don't count ([`PermissionedRegistry._update`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/registry/PermissionedRegistry.sol)). Nobody can add it later, because after registration only non-admin roles are settable on a name. So the grant is non-transferable for its whole life.
  - `expiry`: absolute Unix seconds (`uint64`). The only rule is `expiry > block.timestamp` of the block that includes the transaction, else `CannotSetPastExpiry(expiry)` ([`PermissionedRegistry._register`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/registry/PermissionedRegistry.sol)). There's no minimum or maximum.
  - The requester's one-time address needs no gas: the household's transaction mints the token to it.
  - Resolver: recommend `address(0)` and **no records on grant names** (see Gotchas: records on the household's resolver outlive the grant).
- **Check:** `householdRegistry.getState(uint256(labelhash)) → (status, expiry, latestOwner, tokenId, resource)`, `getStatus(anyId)` (0 available, 1 reserved, 2 registered), `getOwner(anyId)` (zero once expired), `getExpiry(anyId)` (raw), `findOwner(string label)`. From the name alone, walking from the root: `UniversalHelper(0xd453e5bdb62cc3bea84341b1e306319c8ffd7dfe).findExactOwner(bytes dnsName) → address` (zero if expired, unregistered, or any ancestor broke) ([Universal Resolver V2 → UniversalHelper](https://docs.ens.domains/ensv2/universal-resolver-v2)). Expired means `block.timestamp >= expiry` ([`PermissionedRegistry._isExpired`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/registry/PermissionedRegistry.sol)), so an `eth_call` at `latest` flips on the first block whose timestamp reaches `expiry`.
- **Revoke:** `householdRegistry.unregister(uint256 anyId)`. It needs `ROLE_UNREGISTER` on the name or on root, so only the household (and anyone it gives that role) can call it; the requester can't. It emits `LabelUnregistered(tokenId, sender)`, burns the token, bumps both version counters and sets `expiry = block.timestamp`, so the name is available in the same block ([Permissioned Registry → Unregistration](https://docs.ens.domains/ensv2/permissioned-registry)). It **reverts `LabelExpired` if the grant has already expired** (source: `_checkExpiryAndTokenRoles`), so check status first.
- **After expiry or revoke:** `getResolver`, `getSubregistry`, `getOwner`, `ownerOf` return zero, status is `AVAILABLE`, and the label can be registered again with a new token and a fresh role scope ([Mutable Token IDs](https://docs.ens.domains/ensv2/mutable-token-ids)). `latestOwnerOf(tokenId)` still returns the requester after a natural expiry, but zero after `unregister` (token burned). Resolution of the grant *name* does not fail: the Universal Resolver falls back to `sana.pata.eth`'s resolver (it supports ENSIP-10), which serves whatever record that resolver has for the grant's namehash, else its default record, else empty values (see Gotchas).
- **Label constraints:** 1–255 bytes (`NameCoder.assertLabelSize`, called from `LabelStore.setLabel` inside every `register`; reverts `LabelIsEmpty` / `LabelIsTooLong`, [`LabelStore.sol`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/utils/LabelStore.sol), [`NameCoder.sol`](https://github.com/ensdomains/ens-contracts/blob/121dc232df06be28e5eabb34ebfc4bc788498c05/contracts/utils/NameCoder.sol)). The registry doesn't normalize on-chain; clients normalize with ENSIP-15 before hashing ([Name Processing](https://docs.ens.domains/resolution/names)), so generate labels from lowercase `[a-z0-9]` only, which are already normalized (inferred). The label is public forever: `LabelRegistered` carries it in plaintext, and `LabelStore` stores it and emits `Label(bytes32 indexed labelHash, string label)`.

### 5. Records on a Permissioned Resolver

- **Setters** take the DNS-encoded name (`toHex(packetToBytes(name))` in viem), not a namehash: `setText(bytes name, string key, string value)`, `setAddress(bytes name, uint256 coinType, bytes addressBytes)`, `setData(bytes name, string key, bytes value)` (ENSIP-24), `setContenthash`, `setName`, `setABI`, `setInterface`, batched with `multicall(bytes[] calls)` ([Permissioned Resolver → Reference](https://docs.ens.domains/ensv2/permissioned-resolver)). The first write to a name creates its record and emits `Linked(recordId, node, name)`.
- **Reads** go only through `resolve(bytes name, bytes data)`; there are no standalone getters. Supported read profiles: `addr(bytes32)`, `addr(bytes32,uint256)`, `text(bytes32,string)`, `data(bytes32,string)`, `name(bytes32)`, `contenthash(bytes32)`, `hasAddr(bytes32,uint256)`, `ABI(bytes32,uint256)`, `interfaceImplementer(bytes32,bytes4)`; anything else reverts `UnsupportedResolverProfile` ([`AbstractRecordResolver.resolve`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/resolver/AbstractRecordResolver.sol)). **No `pubkey()` profile**, so the household's encryption key goes in a text or data record.
- **Keys for Pata:** ENSIP-5's global key `location` is "a generic location (e.g. "Toronto, Canada")" ([ENSIP-5](https://docs.ens.domains/ensip/5)), and ENSIP-18 says it "should not be assumed to be real coordinates" ([ENSIP-18](https://docs.ens.domains/ensip/18)); it fits "Dharavi, 400017". There's no standard key for a PIN code or an encryption key; ENSIP-5 says a service should declare its own reverse-dot-notation key with at least one dot (e.g. a key under `eth.pata.`). The exact key names are our decision (ADR).
- **Family roles scoped to a key:** `grantSetterRoles(bytes setter, address account)` with `setter = encodeFunctionData(setText, ['0x', key, ''])`; only the selector and the key matter. The caller needs `ROLE_SET_TEXT_ADMIN` (root). Revoke with `revokeRoles(uint256(keccak256(bytes(key))), ROLE_SET_TEXT, account)`. The generic `grantRoles` always reverts on the resolver. Scope is per key, **never per name**: the holder can write that key on every name the resolver serves ([Permissioned Resolver → EAC Integration](https://docs.ens.domains/ensv2/permissioned-resolver)). `ROLE_LINK`, `ROLE_SET_CONTENTHASH`, `ROLE_SET_NAME`, `ROLE_UPGRADE` are root-only. Up to 15 accounts per role per resource ([Enhanced Access Control](https://docs.ens.domains/ensv2/enhanced-access-control)).
- **What logs make public** ([Indexing ENSv2](https://docs.ens.domains/ensv2/indexing)): `TextUpdated(recordId, keyHash, key, value)` and `DataUpdated(…, value)` carry key and value in plaintext; `AddressUpdated` the address; `Linked(recordId, node, name)` the full DNS-encoded name; `EACRolesChanged(resource, account, old, new)` every role holder's address (so family members' addresses); `ResourceArgument(resource, arg)` the key a delegate was given; on registries, `LabelRegistered(tokenId, labelHash, label, owner, expiry, sender)` and `ExpiryUpdated`.

### 6. Aliasing for families

- `linkToNode(bytes sourceName, bytes32 targetNode)` makes `sourceName` (DNS-encoded) use the record `targetNode` (namehash) currently uses; reverts `InvalidRecord` if the target has no record. `linkToRecord(bytes sourceName, uint256 recordId)` links by number; `0` unlinks. Both need root `ROLE_LINK` on that resolver. `getRecordId(bytes32 node)` reads the link ([Permissioned Resolver → Records and Linking](https://docs.ens.domains/ensv2/permissioned-resolver)).
- Resolution follows the link only if the source name reaches **the same resolver instance**: the resolver reads `_recordIds[namehash(name)]`, falling back to the default record (the one linked to the root name `0x00`) ([`PermissionedResolver._record`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/resolver/PermissionedResolver.sol)). Two ways:
  - **Sibling names** such as `ravi.pata.eth` (owned by a family member): the member sets `pataRegistry.setResolver(labelhash("ravi"), householdResolver)`, then the household calls `linkToNode(dns("ravi.pata.eth"), namehash("sana.pata.eth"))`.
  - **Names under the household** such as `ravi.sana.pata.eth`: with no resolver of their own they already fall back to `sana`'s resolver through ENSIP-10, so the household's `linkToNode` alone is enough (inferred from the Universal Resolver's longest-suffix walk).
- Registry-level "namespace aliasing" (`setSubregistry` pointing two names at one registry) is a different feature and not needed ([Registry Hierarchy](https://docs.ens.domains/ensv2/registry-hierarchy)).

### 7. The `*.digipin.eth` wildcard resolver (Pata's only custom contract)

- **How the Universal Resolver reaches it:** it walks from the root, calling `getResolver(label)` and `getSubregistry(label)` at each level and remembering the deepest non-zero resolver ([`LibResolution.findUnvalidatedResolver`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/universalResolver/libraries/LibResolution.sol)). For `39j49ll8t4.digipin.eth` with `digipin.eth`'s resolver set to our contract and no subregistry, the walk stops at `digipin` and returns our resolver at a non-zero offset. A resolver found above the leaf is used only if `supportsInterface(0x9061b923)` returns true (`validateResolver`), otherwise the call reverts `ResolverNotFound` ([Universal Resolver V2 → requireResolver](https://docs.ens.domains/ensv2/universal-resolver-v2)). Nothing is registered per cell. Keep `digipin.eth`'s subregistry empty, so no registered child can shadow a cell (inferred).
- **Interface** ([ENSIP-10](https://docs.ens.domains/ensip/10), [Writing a Resolver](https://docs.ens.domains/resolvers/writing)):
  - `function resolve(bytes calldata name, bytes calldata data) external view returns (bytes memory)`;
  - `supportsInterface(bytes4)` returns true for `0x9061b923` (IExtendedResolver) and `0x01ffc9a7` (ERC-165). The UR checks it with OpenZeppelin's `ERC165Checker.supportsERC165InterfaceUnchecked`, so keep it a cheap pure function (inferred).
  - `data` is the ABI-encoded profile call, whose `bytes32 node` argument the resolver may ignore; the return value must be ABI-encoded exactly as that profile returns it (`abi.encode(string)` for `text`). Revert for unsupported profiles; the UR surfaces resolver reverts as `ResolverError(bytes)` / `UnsupportedResolverProfile(bytes4)` ([ENSIP-23](https://docs.ens.domains/ensip/23)).
- **DNS-encoded name:** each label prefixed by its length byte, ending in `0x00`: `39j49ll8t4.digipin.eth` → `0x0a 3339…34 07 646967697069 6e 03 657468 00` (bytes: `\x0a39j49ll8t4\x07digipin\x03eth\x00`) ([Name Processing → DNS Encoding](https://docs.ens.domains/resolution/names)). The first label is `name[1 : 1 + uint8(name[0])]`; `NameCoder.firstLabel(name)` does it. Clients normalize first, so the resolver sees lowercase (`39J-49L-L8T4` must arrive as a lowercase label).
- **Which record returns coordinates: there is no standard.** No ENSIP defines a coordinates or geo record; the closest, `location`, is free text that "should not be assumed to be real coordinates" ([ENSIP-18](https://docs.ens.domains/ensip/18)). Options: a text record under our own reverse-dot key returning `"lat,lon"` (readable by `getEnsText`), plus `location` for a human string; or a `data` record (ENSIP-24) with ABI-encoded fixed-point values. Decide in an ADR.
- **Universal Resolver:** proxy `0xeEeEEEeE14D718C2B47D9923Deab1335E144EeEe` on mainnet and Sepolia ([Universal Resolver](https://docs.ens.domains/resolvers/universal)); current Sepolia implementation `UniversalResolverV2 0x24e1d8e068620b647ca097f961a61055f4f42d72` behind `ManagedUniversalResolverProxy 0x6d80F2172CFdEc5730fE683860C33d26fC42e6F1` ([deployments](https://docs.ens.domains/learn/deployments#sepolia-ensv2)). Don't hardcode the implementation. A client calls `resolve(bytes name, bytes data) → (bytes result, address resolver)`, or `multicall(bytes[])` inside `data` for several records ([ENSIP-23](https://docs.ens.domains/ensip/23)); in viem that's `getEnsText({ name, key })`.

### 8. ENSIP-26 requester records

From [ENSIP-26](https://docs.ens.domains/ensip/26) (status **draft**, created 2025-05-17):

- `agent-context`: any format suitable for agentic systems (plain text, Markdown, YAML, JSON). It describes the agent and how to interact with it, and may reference ENSIP-25 registrations or `agent-endpoint` records. Published via `text(bytes32,string)`.
- `agent-endpoint[<protocol>]`: the key includes the protocol in square brackets; the value MUST be a valid URL (`https://`, `http://`, or `ipfs://{cid}`). Listed protocols: `mcp`, `a2a`, `web`; others MAY be used. Examples: `agent-endpoint[mcp]`, `agent-endpoint[web]`.
- Optional: [ENSIP-25](https://docs.ens.domains/ensip/25) `agent-registration[<registry>][<agentId>]` with a non-empty value (conventionally `"1"`), linking the name to an ERC-8004 registry entry.
- Writes are ordinary `setText` calls on the requester name's resolver.

## Limits

- **Labels:** 1–255 bytes each (`NameCoder.assertLabelSize`). No limit on name depth found.
- **Expiry:** `uint64` Unix seconds; a name is expired once `block.timestamp >= expiry`; a new registration needs `expiry > block.timestamp`; no minimum or maximum in the registry (source). `renew` can't reduce expiry. `.eth` 2LDs have a 28-day grace period, then a 21-day premium starting near $100M and halving daily ([ETH Registrar](https://docs.ens.domains/ensv2/eth-registrar)); subname registries have no grace period (source: `_isExpired`).
- **Sepolia blocks:** 12.1 s average over the last 1,000 blocks (`cast block 12050093 -f timestamp` minus `cast block 12049093 -f timestamp` = 12,096 s, run 2026-11-03 IST against `https://ethereum-sepolia-rpc.publicnode.com`). A grant's expiry is observed on the first block at or after it, so up to ~12 s late.
- **EAC:** 32 regular + 32 admin roles per contract; up to 15 accounts per role per resource (`EACMaxAssignees`) ([Enhanced Access Control](https://docs.ens.domains/ensv2/enhanced-access-control)).
- **Commit-reveal:** `MIN_COMMITMENT_AGE` 60 s, `MAX_COMMITMENT_AGE` "typically 24 hours" (docs); Sepolia values **open**.
- **Fees:** 3 chars $640/yr, 4 chars $160/yr, 5+ chars $8/yr, in MockUSDC on Sepolia.
- **Proxies:** each Verifiable Factory deployment writes 77 bytes of proxy code; logic and implementation are shared ([Verifiable Factory](https://docs.ens.domains/ensv2/verifiable-factory)).
- **Gas:** no figures in the docs; **open** (estimate at kick-off).
- **Rate limits:** none in ENS; the RPC provider's limits apply (Anon-RPC note).

## Gotchas

1. **Grant records on the household's resolver survive the grant.** The Permissioned Resolver keys records by namehash and never checks the registry ([`AbstractRecordResolver.resolve`](https://github.com/ensdomains/contracts-v2/blob/07e55a056f5b6a9c90119f501bdd05714e67dddd/contracts/src/resolver/AbstractRecordResolver.sol)). After a grant expires or is unregistered, its registry entry returns no resolver, the Universal Resolver falls back to `sana.pata.eth`'s resolver via ENSIP-10, and that resolver still serves any record written for the grant's name. So: write no records for grant names on the household resolver (liveness is ownership, which needs no records), or put them on a separate resolver instance that no ancestor uses, or unlink on revoke (`linkToRecord(name, 0)`, which can't happen on natural expiry). (Inferred from source; confirm at kick-off.)
2. **"Stops resolving" means "loses its owner".** An expired grant name doesn't make the UR revert; it resolves through the parent's resolver to the default record or empty values. The courier link must decide liveness from the registry (`getStatus`/`getOwner` on the household registry, or `UniversalHelper.findExactOwner`), not from whether resolution returns data.
3. **Never write records to the root name `0x00`** on the household resolver: they become the default record for every unlinked name under `sana.pata.eth`, including every grant label and every random label anyone queries ([Permissioned Resolver → The Default Record](https://docs.ens.domains/ensv2/permissioned-resolver)).
4. **`unregister` reverts on an expired grant** (`LabelExpired`). Revoke must read status first and treat "already expired" as done.
5. **A short grant can revert at mining time.** `register` requires `expiry > block.timestamp` of the including block. A 20-second grant computed from the phone's clock may already be in the past if inclusion takes two blocks (~24 s). Compute expiry from the latest block's timestamp plus a margin for inclusion, and treat `CannotSetPastExpiry` as a retry.
6. **The docs' `ALL_ROLES` example blocks emancipation.** `UNEMANCIPATED_ROLE_BITMAP` in the deployed code includes `ROLE_UPGRADE` and `ROLE_UPGRADE_ADMIN` as well as the resolver, subregistry, unregister and transfer roles, so an emancipated `pata.eth` registry can never be upgraded. (The docs page says upgrade roles block emancipation only for `UserRegistry`; in the deployed source the base check includes them. Same result for us, since our registries are `UserRegistry` proxies.)
7. **Emancipating `pata.eth`'s registry is not enough.** The `pata.eth` owner can still swap the subregistry pointer until it revokes `ROLE_SET_SUBREGISTRY(+_ADMIN)` on `pata` (flow 2), and everything depends on `pata.eth` staying registered.
8. **Token IDs change** on every `grantRoles`/`revokeRoles`, re-registration and unregistration. Store labelhashes, never token IDs; most functions accept any of labelhash, token ID or resource (`anyId`) ([Mutable Token IDs](https://docs.ens.domains/ensv2/mutable-token-ids)).
9. **Resolver roles cover the whole resolver.** A family member given `ROLE_SET_TEXT` for one key can write that key on every name the household resolver serves, grants included. Isolate writers with separate resolver instances ([Issuing Subnames in ENSv2 → Limit a Writer to a Group of Names](https://docs.ens.domains/ensv2/subnames)).
10. **Public by design:** every label (twice: `LabelRegistered` and `LabelStore`), every owner and expiry, every record key and value, every role holder. Matches the CLAUDE.md invariant; the new detail is that role grants publish family members' addresses.
11. **`setApprovalForAll` on a registry** hands an operator all of the owner's roles on all of its names, with no scoping ([Permissioned Registry → Operator Approval](https://docs.ens.domains/ensv2/permissioned-registry)). Never call it.
12. **Name ownership doesn't grant resolver roles.** A subname owner using someone else's resolver gets `EACUnauthorizedAccountRoles` on writes ([For App Developers → Who Can Write](https://docs.ens.domains/ensv2/tutorial-app-developers)); each household needs its own resolver for its own records.
13. **A subregistry pointer must hold code.** Set it only after the proxy is deployed: the UR calls `getResolver`/`getSubregistry` on it during every lookup below that name (inferred).
14. **One deployer, one salt, one proxy:** `deployProxy` uses CREATE2 with `keccak256(msg.sender, salt)`, so redeploying with the same salt from the same key reverts; bump the `version` in the salt (source).
15. **Sepolia payment token list differs between docs pages.** The readiness page names Circle's USDC `0x1c7D…7238`, a test USDC `0x16f9…8aa8e` and a test DAI `0x2780…9664`; the deployments table names `MockUSDC 0x240b…14aa` and `MockDAI 0xf6fa…572b`. Check `isPaymentToken` on the oracle (**open**).

## Contradictions with idea.md

1. **ENSIP-26 key name.** idea.md: "Each name publishes the standard agent records `agent-context` and `agent-endpoint` … the hand-off goes over TLS to the second." ENSIP-26 has no bare `agent-endpoint` key: it is `agent-endpoint[<protocol>]`, with `mcp`, `a2a` and `web` listed ([ENSIP-26](https://docs.ens.domains/ensip/26)). The consent hand-off fits `agent-endpoint[web]` or a protocol value of our own ("Additional protocol values MAY be used"). ENSIP-26 is also still a draft.
2. **"An expired grant stops resolving by itself."** idea.md (Sponsor plan, verified 2026-10-22): "An expired name's owner and resolver return zero, so an expired grant stops resolving by itself", and "On expiry the subname stops resolving". Owner and resolver do return zero ([Permissioned Registry](https://docs.ens.domains/ensv2/permissioned-registry)), but resolution then continues at the nearest ancestor's ENSIP-10 resolver ([Universal Resolver V2 → Resolution](https://docs.ens.domains/ensv2/universal-resolver-v2)), here the household's own Permissioned Resolver, which serves records by namehash regardless of registry state (source, Gotcha 1). The grant only "stops resolving" if no ancestor resolver holds records for it; the reliable signal is the owner.
3. **"Their own emancipated registry."** idea.md (scale row): "Households that want a name no provider can touch get their own emancipated registry, as in the demo." What protects `sana.pata.eth` from the provider is that the registry *containing* `sana` (`pata.eth`'s) is emancipated and `pata.eth`'s subregistry pointer is locked ([Permissioned Registry → Emancipation Across the Hierarchy](https://docs.ens.domains/ensv2/permissioned-registry)). The household's own grant registry must stay un-emancipated, because root `ROLE_UNREGISTER`, the household's revoke power, is one of the roles that block emancipation (`UNEMANCIPATED_ROLE_BITMAP`). The Sponsor plan's wording ("the registry is emancipated, so the parent can't control them") is right if "the registry" means `pata.eth`'s.
4. **"`unregister()` revokes at once."** True for a live grant, but `unregister` reverts `LabelExpired` on a grant that has already expired (source, Gotcha 4). Not a design problem, only an error path the revoke button must handle.
5. Not idea.md but research.md: the Sponsors table says "ENSv2 (live on mainnet)". The deployments page says the mainnet ENSv2 contracts are "deployed on Ethereum Mainnet ahead of the ENSv2 launch. Until the launch completes, resolution and registrations on Mainnet continue through the ENSv1 contracts" ([deployments](https://docs.ens.domains/learn/deployments)). Irrelevant for a Sepolia build.

Confirmed as written in idea.md: expiry at `block.timestamp >= expiry` with no minimum; `unregister()` acts in the same block; the UR hands a child name to the parent's resolver only if it implements `resolve(bytes,bytes)`; aliasing is `linkToNode` inside one Permissioned Resolver and needs `ROLE_LINK`; resolver roles scope to a record key, never to a name; a resolver instance is per account; `deployProxy(implementation, salt, data)`; `LabelRegistered` logs the label and `TextUpdated` the value; ETHRegistry `0xd4eb…a8b4` with `getStatus` 0/1/2; a 4 m-cell wildcard needs no registrations; EAC can't cap a grant's length.
