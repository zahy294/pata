**Read the usage policies before using either public service.** The OSM Foundation's Nominatim policy asks that an LLM suggesting the service "prominently point to this usage policy and explain the restrictions", and says "Code generated by LLMs must adhere to all terms laid out in this policy" ([policy](https://operations.osmfoundation.org/policies/nominatim/), "Usage in LLMs", added 2026-05-11 in [owg-website fd69370](https://github.com/openstreetmap/owg-website/commit/fd6937012a)). In short: at most 1 request per second for the whole app, an identifying User-Agent or Referer, visible attribution, no autocomplete, no systematic or bulk queries, no personal data. The public API "is only permitted where the application developer has made a deliberate, informed decision to use it and is directly responsible for complying with this policy" (same section). A person on the team makes that decision; this note is the input to it.

## Install and setup

- Nothing to install, no key, no sign-up. Nominatim is HTTP GET (`/search`, `/reverse`, `/status` on `https://nominatim.openstreetmap.org`). Overpass takes a query by GET or POST (`data=`) at `https://overpass-api.de/api/interpreter` ([Search](https://nominatim.org/release-docs/latest/api/Search/), [Reverse](https://nominatim.org/release-docs/latest/api/Reverse/), [Status](https://nominatim.org/release-docs/latest/api/Status/), [wiki](https://wiki.openstreetmap.org/wiki/Overpass_API)).
- **Call both from our one small server, not the browser.** This is inferred, for five reasons:
  1. The Claude tool loop already runs on the server, because `ANTHROPIC_API_KEY` is server-only (`.env.example`).
  2. Limits count per app. The 1 request/second limit applies "per website/application: the sum of traffic by all your users" ([Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/)). For Overpass, "If you have an app or website, then the usage counts towards the sum of requests made by all your users" ([lonvia, 2026-08-26](https://community.openstreetmap.org/t/140598/171)). One server-side queue enforces this.
  3. The policy says "If at all possible, set up a proxy and also enable caching of requests". Apps "must make sure that they can switch the service at our request at any time ... without requiring a software update" ([policy](https://operations.osmfoundation.org/policies/nominatim/)). A static IPFS build can't switch without a rebuild.
  4. overpass-api.de has "banned many platforms for fast-deployment of AI-generated apps like lovable.app or netlify.app" ([lonvia, 2026-08-11](https://community.openstreetmap.org/t/140598/157)). A browser call from a shared IPFS gateway origin could hit a similar Referer ban (inferred; untested).
  5. Privacy: the OSM servers see our server's IP instead of the household's (see Privacy below).
- **Set a custom User-Agent on the server.** Something like `Pata/0.1 (ETHGlobal Mumbai hackathon; +<repo URL>; <team email>)`. Sources:
  - Nominatim: "stock User-Agents as set by http libraries will not do" ([policy](https://operations.osmfoundation.org/policies/nominatim/)).
  - FOSSGIS, which runs overpass-api.de: "Valid HTTP User-Agent identifying the application. User agents of libraries are not sufficient". FOSSGIS also wants an operator email address on the website that is "easily identifiable and directly reachable" ([FOSSGIS terms](https://www.fossgis.de/arbeitsgruppen/osm-server/nutzungsbedingungen/), modified 2026-10-29).
  - "No stock UAs, no UA faking, no UA rotation" ([lonvia, 2026-04-19](https://community.openstreetmap.org/t/140598/74)).
  - Node's `fetch` sends a stock UA unless we set the header (inferred).
- **Endpoint URLs come from config.** FOSSGIS: "The URLs of our services should not be hardcoded into the app". Following CLAUDE.md, that means two new names in `.env.example`, such as `NOMINATIM_URL` and `OVERPASS_URL`. This is a suggestion; this note doesn't edit that file.
- **One outbound queue per service:**
  - Nominatim: at most 1 request/second.
  - Overpass: one request at a time ("Scripts are limited to one connection", [FOSSGIS terms](https://www.fossgis.de/arbeitsgruppen/osm-server/nutzungsbedingungen/)). After a 429 or 406, wait at least 30 s ([lonvia, 2026-08-11](https://community.openstreetmap.org/t/140598/157)).
  - The model asks for a search; plain code decides whether and when it runs, dedupes it, and serves repeats from the cache.

## What Pata uses

These flows follow idea.md's address AI. Haiku extracts the locality and PIN code. The locality's box limits every later search. A larger model ranks landmarks inside the box, and plain code places pins on street geometry.

### 1. Locality → bounding box (Nominatim search)

You can use free-form or structured parameters, but not both: structured parameters "Cannot be combined with the `q=<query>` parameter" ([Search](https://nominatim.org/release-docs/latest/api/Search/)).

- **Use the locality, not the PIN code, for the box.** Request: `GET /search?q=Dharavi, Mumbai&countrycodes=in&format=jsonv2&addressdetails=1&namedetails=1&limit=1`.
  - Live result, 2026-11-03: the administrative boundary way 280668341, `addresstype: "suburb"`, with `boundingbox ["19.0368844","19.0542277","72.8484246","72.8651342"]`. That is about 1.9 km by 1.8 km, and `namedetails` included `name:hi` and `name:mr` "धारावी".
  - Adding `featureType=settlement` restricts results to places "from 'state' down to 'neighbourhood'" (Search).
- **The PIN code works as a cross-check.** Request: `GET /search?postalcode=400017&countrycodes=in&format=jsonv2&addressdetails=1&limit=1`.
  - Live result, 2026-11-03: `category "place"`, `type "postcode"`, `postcode_id "Pin:400017"`, centroid 19.0419, 72.8556, `address.suburb "Dharavi"`.
  - Its `boundingbox` was `["18.9967167","19.0870295","72.8081000","72.9030689"]`, about 10 km by 10 km. That's far wider than the neighbourhood, and would let a Hanuman Mandir across the city win.
  - The docs explain why: a postcode result is "a postcode point created from all mapped postcodes of the same name", with no `osm_type`/`osm_id` ([Output, "OSM reference"](https://nominatim.org/release-docs/latest/api/Output/)). And "Most places in OSM don't have a postcode, so Nominatim tries to interpolate one" ([FAQ 7](https://nominatim.org/release-docs/latest/api/Faq/)).
  - Use the PIN code to confirm that the locality result's `address.postcode` or `suburb` matches. India's settings normalise PIN codes with pattern `(ddd) ?(ddd)` → `\1\2` ([country_settings.yaml](https://github.com/osm-search/Nominatim/blob/master/settings/country_settings.yaml), entry `in`).
- **Parameters:**
  - `countrycodes=in` is a hard filter; the structured `country` field is only fuzzy (Search).
  - Always send `format`: without it, nominatim.openstreetmap.org forwards the request "to the Web UI" (Search). `jsonv2` renames `class` to `category` and adds `place_rank` ([Output](https://nominatim.org/release-docs/latest/api/Output/)).
  - `limit` defaults to 10 and "Cannot be more than 40" (Search).
  - `addressdetails=1` adds the `address` breakdown. `namedetails=1` adds "language variants, older names, references and brand" (Search).
- **`boundingbox` order:** "min latitude, max latitude, min longitude, max longitude", as strings ([Output, "boundingbox"](https://nominatim.org/release-docs/latest/api/Output/)).

### 2. A named landmark inside the box (Nominatim search, bounded)

`GET /search?q=Hanuman Mandir&viewbox=<minlon>,<minlat>,<maxlon>,<maxlat>&bounded=1&countrycodes=in&format=jsonv2&namedetails=1&limit=10&accept-language=mr,hi,en`

- **`viewbox` filters only with `bounded=1`.** It's written `<x1>,<y1>,<x2>,<y2>` where "`x` is longitude, `y` is latitude", and on its own it's only a "Boost parameter". `bounded=1` "turns the 'viewbox' parameter ... into a filter parameter, excluding any results outside the viewbox" (Search).
- **The `boundingbox` → `viewbox` conversion reorders the numbers:** `viewbox = bb[2],bb[0],bb[3],bb[1]`. A swapped order still forms some box, so it fails silently (inferred).
- **Don't use Nominatim to list everything in an area.**
  - Special phrases such as `[pub]` work in a small bounded box, but "There is no guarantee that the result returns all objects in the area" (Search).
  - The policy bans "downloading all POIs in an area" ([policy](https://operations.osmfoundation.org/policies/nominatim/), "Systematic queries").
  - The docs point to Overpass for that job (Search; [FAQ 6](https://nominatim.org/release-docs/latest/api/Faq/)).
- **Languages:** `accept-language` takes a comma-separated list. A request without it falls back to the `Accept-Language` header; with no header, results come in "the local language" (Search).
  - India's defaults are `hi, en` ([country_settings.yaml](https://github.com/osm-search/Nominatim/blob/master/settings/country_settings.yaml)).
  - Marathi appears only if requested, and only where `name:mr` exists (inferred).
- `layer=poi` restricts results to points of interest. `exclude_place_ids` pages past results already seen (Search).

### 3. Landmarks and streets inside the box (Overpass)

Send one query per locality, cache it, and match the spoken landmark names against it in code or in the model's context. Shape:

```
[out:json][timeout:25][maxsize:67108864][bbox:<south>,<west>,<north>,<east>];
(
  nwr["amenity"="place_of_worship"]["name"];
  nwr["shop"]["name"];
  nwr["amenity"~"^(school|college|hospital|clinic|pharmacy|bank|atm|police|post_office)$"]["name"];
  nwr["landuse"]["name"];
);
out tags center;
way["highway"];
out tags geom;
```

- **Bounding box order** is "southern-most latitude, western-most longitude, northern-most latitude, eastern-most longitude". So from Nominatim: `bb[0],bb[2],bb[1],bb[3]`.
  - "constituent ways or relations may extend beyond these bounds" ([Overpass QL, Global bounding box](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_QL#Global_bounding_box_(bbox))).
  - A `&bbox=` URL parameter uses the reverse, lon-lat order (same section).
  - The manual gives the same edge order ([Bounding Boxes](https://dev.overpass-api.de/overpass-doc/en/full_data/bbox.html)).
- **Output modes** ([Data Formats](https://dev.overpass-api.de/overpass-doc/en/targets/formats.html)):
  - `out tags center` gives tags plus one coordinate per object, which "is just in the middle of the bounding box that encloses the object", not a true centroid.
  - `out geom` adds coordinates to ways.
  - `[out:json]` is OSM JSON, not GeoJSON.
- **`[timeout:]` and `[maxsize:]`** declare run time (seconds) and memory (bytes). The defaults are 180 s and 512 MiB, and a query that exceeds either is aborted. The server admits a query only if its declared limits use "at most half of the remaining available resources", so small declarations get in sooner ([manual, Commons](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html); [Overpass QL, Settings](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_QL#Settings)).
- **Multilingual names:** India's convention is "the Roman alphabet ('English') for the name key", the local language in `name:xx`, and other well-known names in `alt_name` ([OSM wiki, India](https://wiki.openstreetmap.org/wiki/India#Naming_in_different_scripts_and_languages)).
  - So match against `name`, `alt_name`, `name:hi`, `name:mr` and `name:en`. All of them come back in `tags` with no extra query.
  - Hindi and Marathi share Devanagari, so the same string can appear in both (seen live for Dharavi).
- **Why one query per locality:** Pata's ask is the overload pattern, "queries that are looking for a certain type of OSM data around a point or in an area" ([lonvia, 2026-09-24](https://community.openstreetmap.org/t/140598/182)). One cached query per locality keeps us far from that, and the servers learn the locality but not which landmarks the household named (inferred).

### 4. Dropped pin → locality (Nominatim reverse)

`GET /reverse?lat=<lat>&lon=<lon>&zoom=14&format=jsonv2&addressdetails=1&accept-language=en`

- **Zoom** sets the detail: 10 city, 12 town/borough, 13 village/suburb, 14 neighbourhood, 18 building (the default) ([Reverse](https://nominatim.org/release-docs/latest/api/Reverse/)).
- **Reverse defaults to `format=xml`**, and `addressdetails` defaults to 1 (Reverse).
- **The result can be across a boundary.** Reverse returns "the closest object to the point you asked for and then returns the address of that object", so near a boundary the suburb can be the neighbour's ([FAQ 2–3](https://nominatim.org/release-docs/latest/api/Faq/)).
- **Don't send the exact pin.** That breaks CLAUDE.md's invariant "The model and map search receive only the spoken way to the door". Instead, check in code which cached locality box contains the pin, or reverse-geocode a point rounded to 2 decimals (about 1.1 km) (inferred).

### 5. Health checks

- **Nominatim:** `GET /status?format=json` returns `{"status":0,"message":"OK","data_updated":"2026-11-03T14:11:34+00:00","software_version":"5.3.0","database_version":"5.3.99-3"}` (live, 2026-11-03). The JSON form answers HTTP 200 whenever it runs and sets a non-zero `status` on error ([Status](https://nominatim.org/release-docs/latest/api/Status/)).
- **Overpass:** `GET https://overpass-api.de/api/status` (live, 2026-11-03) returned plain text: `Connected as: 4094309001`, `Current time: 2026-11-03T14:13:51Z`, `Announced endpoint: lambert.openstreetmap.de/`, `Rate limit: 2`, `2 slots available now.` and a list of running queries. "Connected as" is the user number the server derived from the caller's IP ([manual, Commons](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)).

## Fallbacks if limits bite

Self-hosting is out of scope. Everything below is configured by URL, so a switch is an env change.

- **Overpass:** `https://overpass.private.coffee/api/interpreter` has no rate limit and no key, and asks for notice only for large projects (wiki instance table). Second choice: the cached locality answers from the demo kit. VK Maps is hosted in Russia, which is weaker for a privacy pitch (inferred).
- **Geocoding, Photon** (`https://photon.komoot.io/api/?q=…&lat=…&lon=…&lang=…`, reverse at `/reverse`): OSM-based and run by komoot. "You can use the API for your project, but please be fair - extensive usage will be throttled. We do not guarantee for the availability" ([photon.komoot.io](https://photon.komoot.io/), read 2026-11-03). It biases results toward a point rather than filtering to a box (inferred from the examples on that page; check bbox support at kick-off).
- **Geocoding, LocationIQ:** the free plan needs a sign-up. It allows "5000 requests /day", "2 requests /second" and 60 a minute, with "Limited Commercial Use" ([pricing](https://locationiq.com/pricing), read 2026-11-03). It's Nominatim-compatible (inferred; not checked). The user prefers free tiers; this one costs nothing but needs an account and a key on the server.

## Caching, licence and attribution

- **Licence:** Nominatim results are "Data © OpenStreetMap contributors, ODbL 1.0" (the `licence` field, live). FOSSGIS: "The use of OpenStreetMap data is subject to the terms of the Open Database License 1.0" ([FOSSGIS terms](https://www.fossgis.de/arbeitsgruppen/osm-server/nutzungsbedingungen/)).
- **Cached geocoding results are fine.** The OSMF's [Geocoding Guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Geocoding_-_Guideline) (endorsed 2017-08-24) says "Individual Geocoding Results are insubstantial database extracts". They "may be stored and used together with other proprietary or third party data without having a share-alike impact", as long as they aren't aggregated into "the whole or a substantial part of the OSM database". Its worked example is a search app that caches results "both server side and on-device", which triggers no share-alike but must credit OSM.
  - Caching is also what the policies ask for: "set up a proxy and also enable caching" and "Results must be cached on your side" ([Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/)).
  - The policies set no maximum cache lifetime (none found). Pata's cache can live as long as the demo; key it by `osm_type`+`osm_id`, since `place_id` "is not a persistent id" ([Output](https://nominatim.org/release-docs/latest/api/Output/)).
  - What gets cached is only the query (landmark names, locality) and the public OSM answer. Never cache the household's pin or sentence, because CLAUDE.md requires exact address data to be stored only encrypted.
- **The cached Overpass answers for the demo kit are probably a "substantial" extract.**
  - The [Substantial Guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Substantial_-_Guideline) treats as not substantial "Less than 100 Features", or more only if "non-systematic". It also says "The systematic extraction of all eating places within an area ... would be considered to be systematic" and "we regard repeated small extractions as one big extraction!".
  - The Geocoding Guideline exempts a collection only if it is "not a systematic attempt to aggregate all or substantially all Primary Features of a given type ... within a geographic area city-sized or larger". Dharavi is smaller than a city, so that exemption may apply (inferred; not settled).
  - Safe course (inferred): ship the cached locality files as unmodified OSM data under ODbL 1.0. Keep them in their own folder with a licence notice and the attribution, and don't fold them into an MIT-licensed database.
  - Using ODbL data in a public app is fine. Share-alike bites only on a modified "Derivative Database" that is publicly used (Geocoding Guideline, citing ODbL §4.4).
- **Attribution:** "Applications that incorporate such a geocoder must credit OpenStreetMap" ([Attribution Guidelines, Geocoding](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines)). "Attribution must be legible and understandable", and "“© OpenStreetMap contributors”" is acceptable (same page).
  - FOSSGIS's suggested HTML is `Data © <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a> contributors (<a href="https://opendatacommons.org/licenses/odbl/index.html">ODbL</a>)`, plus a link to `https://openstreetmap.org/fixthemap` ([FOSSGIS terms](https://www.fossgis.de/arbeitsgruppen/osm-server/nutzungsbedingungen/); the CC-BY-SA part of their snippet is for their tiles).
  - Put it on the map screen, the pin-confirmation screen and the courier view; MapLibre's attribution control can carry it (inferred).

## Privacy (for CROPS)

What each request reveals, if it is sent from our server:

- **To the OSM Foundation (Nominatim):**
  - **Request data:** our server's IP, our User-Agent, any Referer, the time, and the request itself (the query string: landmark name or locality, `viewbox`, `accept-language`). The OSMF records "(a) IP address, (b) browser and device type, (c) operating system, (d) referring web page, (e) the date and time ... and (f) the pages accessed" for apps using its APIs ([OSMF privacy policy](https://osmfoundation.org/wiki/Privacy_Policy), "Personal data we receive automatically").
  - **Uses:** operations, "anonymised, summarised data ... offered publicly", and "analysing nominatim queries for missing addresses and postcodes and providing such data to the OSM community" (same section).
  - **Storage:** data is "stored in the United Kingdom and the Netherlands" (same policy).
  - **Retention:** the only period stated is 180 days for Piwik usage data. A retention period for API request logs isn't stated (not found).
  - The policy also asks: "Please do not submit personal data or other confidential material to any of our services" ([Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/)).
- **To FOSSGIS (overpass-api.de):**
  - **Request data:** our server's IP and User-Agent, the time, and the query body, which includes the locality's box.
  - **What the policy says:** FOSSGIS's privacy policy lists server logs of "Browsertyp und Browserversion, verwendetes Betriebssystem, Referrer URL, Hostname des zugreifenden Rechners, Uhrzeit der Serveranfrage", says they "sind nicht bestimmten Personen zuordenbar" (can't be traced to particular people), and gives no retention period ([Datenschutzerklärung](https://www.fossgis.de/datenschutzerkl%C3%A4rung/), section 3).
  - **What the operators do in practice:** they meter usage "per IP and per app" ([lonvia, 2026-09-24](https://community.openstreetmap.org/t/140598/182)) and analyse user agents (same post).
- **Net effect (inferred):**
  - Neither operator learns the household's IP, room number or name.
  - Nominatim sees the locality and each landmark name the model searches for. With Overpass done per locality, Overpass sees only the locality box.
  - Coarsest design: Nominatim resolves only the locality, and all landmark matching runs against the cached Overpass answer. The household's landmarks then never leave our server except to the model.

## Gotchas

- **Four coordinate orders:**
  - Nominatim `boundingbox`: lat, lat, lon, lon.
  - Nominatim `viewbox`: lon, lat, lon, lat.
  - Overpass `[bbox:]`: south, west, north, east.
  - Overpass `&bbox=` URL parameter and GeoJSON: lon, lat.

  Put all conversions in one tested module.
- **Numbers are strings** in Nominatim JSON (`lat`, `lon`, `boundingbox`) (live responses, 2026-11-03).
- **The PIN code's box is about 10 km wide** (live, 400017). Don't use it as the search box.
- **`place_id` changes between servers and reimports.** Key caches on `osm_type`+`osm_id` ([Output](https://nominatim.org/release-docs/latest/api/Output/)).
- **No autocomplete.** Search on submit only ([policy](https://operations.osmfoundation.org/policies/nominatim/)).
- **Model-driven calls need a code-side budget.** "Clients sending repeatedly the same query may be classified as faulty and blocked" (policy). Cap searches per address, and dedupe.
- **overpass-api.de is overloaded right now.** "do not expect high reliability" ([wiki](https://wiki.openstreetmap.org/wiki/Overpass_API#Public_Overpass_API_instances)). In late September one of its two servers served data two days stale ([thread, posts 178–182](https://community.openstreetmap.org/t/140598/178)). The demo kit's cached answers are required, not optional.
- **Shared cloud IPs** may already be quota-banned; 15k IPs were at the time of [lonvia's 2026-09-24 post](https://community.openstreetmap.org/t/140598/182). Check from the real host.

## Contradictions with idea.md

1. **What the map search sees.**
   - idea.md, EF CROPS "P": "The model provider and OpenStreetMap's search see the spoken address and its locality once, at setup."
   - Against it: "Please do not submit personal data or other confidential material to any of our services" ([Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/), "Privacy").
   - A second problem: Overpass isn't run by OpenStreetMap; overpass-api.de is FOSSGIS's ([FOSSGIS terms](https://www.fossgis.de/arbeitsgruppen/osm-server/nutzungsbedingungen/), "Scope").
   - Fix: send landmark names and the locality, never the spoken address, from our server's IP. The CROPS line should name both operators and say exactly what they see.
2. **Shipping after the hackathon.**
   - idea.md, Best CROPS App, "Could it ship after the hackathon": "Yes, as one of DHRUVA's many address providers."
   - Against it:
     - "Applications and services whose primary function is related to geocoding must run their own service" ([Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/)).
     - "Commercial use is only permitted if the use of the services does not constitute a substantial part of an online offering" ([FOSSGIS terms](https://www.fossgis.de/arbeitsgruppen/osm-server/nutzungsbedingungen/)).
     - "Setting up an app for more than just OSM mappers and relying on the public instances as backend" is listed as problematic ([Overpass manual](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)).
   - Fix: the answer stays yes, but with its own Nominatim and Overpass, or a paid provider.
3. **The licence of the cached map data.**
   - idea.md, CROPS "O": "MIT licence; the app builds and runs from the repo alone." With the Offline demo kit's "cached Overpass answers for the demo locality", the repo would also hold OSM data.
   - Against it: that data is under ODbL 1.0 ([FOSSGIS terms](https://www.fossgis.de/arbeitsgruppen/osm-server/nutzungsbedingungen/); Nominatim's `licence` field), and an all-features locality extract is likely "Substantial" ([Substantial Guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Substantial_-_Guideline)).
   - Fix: keep those files under ODbL with attribution, and say so next to the MIT licence.
4. **The PIN code's box.**
   - idea.md, "Why this model and architecture?": "Haiku 5.5 first extracts the address parts, including the locality and PIN code. That locality's bounding box then limits every map search to the neighbourhood."
   - This works only for the locality's own box. The PIN code's box for 400017 is about 10 km wide (live search, 2026-11-03), because Nominatim builds postcode results as "a postcode point created from all mapped postcodes of the same name" ([Output](https://nominatim.org/release-docs/latest/api/Output/)).
   - Fix: the box comes from the locality's boundary; the PIN code only cross-checks.
