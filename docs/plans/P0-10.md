# P0-10: approve a grant

**Goal:** prepare the selected-language encrypted grant payload and household index/history in one Arkiv batch, mint a role-free expiring ENS grant, then return the courier link. Verify live expiry/revocation/permission rows separately; consent-screen acceptance waits for frontend integration.

**Files:** blockchain-owned `src/lib/ens/grants.ts`, required pinned ABI errors, `src/lib/arkiv/` batch implementation, `src/lib/flows/approve-grant.ts` and pure grant-data helpers, tests and opt-in live harness; this plan, P0-3 evidence and blockchain checklist. Preserve shared contracts and frontend-owned formatter/screen.

**Tests first (confirmed):** public expiry/payload helpers for fixed arithmetic, validation and exact selected-language data; sepoliaNow/mintGrant at chain I/O for registration, successful receipts and one typed expiry retry; createGrantBatch at the SDK seam for encryption recipients, index fields, expirations/readonly and created-key order; approveGrant for orchestration, cleanup and safe failures. Real grant permission tests remain separate. Existing keys and sealing stay real.

**Research read:** AGENTS.md including Deploys: never, blockchain role, plan approval flow, ENSv2 section 4 and Gotcha 5, Arkiv batch/atDate notes and installed SDK types, ADRs 0002/0004/0008, glossary and TDD skill.

**Decisions:** base expiry on latest Sepolia timestamp plus requested duration and the shared margin. Only a decoded CannotSetPastExpiry permits one mint retry. Refreshing expiry must also rebuild the sealed payload/index/history and replace the unissued history entry, so the returned link/payload/ENS expiry agree; the obsolete payload expires at its original deadline. Keep session bytes only within approval and overwrite/drop local references after link construction or failure. Never retry an uncertain broadcast or log raw errors. All application RPC uses the shared module.

**Risks / handoff:** formatCourierLink and the consent screen are frontend-owned stubs; user directed implementing/verifying the blockchain flow and recording these dependencies. Preflight link construction before paid work so a missing formatter cannot strand a minted grant. No live Worker mutation/deployment commands or owner scripts. Live grant tests may deploy/fund only throwaway testnet household contracts using the development wallet at runtime; never open/print secret files or private keys. A real working consent-screen link cannot be claimed until frontend is integrated. Team chat destination is not configured; return the handoff text without sending it elsewhere.
