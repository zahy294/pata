# P1: page transitions

- **Goal:** add the approved roughly 300 ms page reveal in Pata's green, cream and gold theme on phones and laptops; keep the header stationary and reduced-motion navigation instant.
- **Files:** a persistent client component in the shared layout, namespaced CSS, browser navigation tests, scoped Hue motion tokens and research notes.
- **Tests first:** user-approved browser seam: internal links reveal the arriving page; direct loads and courier fragments retain their normal behavior; rapid navigation never blocks interaction; Back/Forward works; reduced motion disables the effect. One red/green slice at a time.
- **Research read:** `docs/research/page-transitions.md`, `frontend-intro-components.md`, local Next usePathname/template/view-transition docs, Hue and the existing `docs/design/pata-intro.yaml` model.
- **Design:** short upward settle and fading green/gold door-jamb accent; no full-screen curtain, loading indicator or departing-page snapshot. Preserve the existing intro separately.
- **Risks:** no copied Pro/library components or new dependency. Keep the wrapper unkeyed, leave links/history/focus/scroll to Next, observe only pathname, cancel prior animations, and retain visible content without animation support. Inspect fixed descendants before choosing the animated region. Physical-phone/mobile-data and funded end-to-end checks remain owner verification; this change does not alter chain or server flows.
- **Result:** implemented an unkeyed layout wrapper with a 300 ms, 6px arrival settle and fading green/gold door-jamb accent. The header remains outside it. Direct loads skip motion; pathname-only observation leaves fragments and query changes to the router. Old animations cancel on navigation/unmount, and changing reduced-motion preferences cancels an active reveal. Base content stays visible and interactive when browser animation support is absent. No new dependency or copied component source.

Validation: the navigation-reveal test failed before implementation; reduced-motion navigation failed before its guard was added. All 40 intro/loader/navigation browser checks pass across Chrome desktop and phone emulation, and all 14 navigation checks also pass against the production static export. The browser samples short-lived motion before clicking so runner latency cannot miss it; header checks allow ordinary link hover color transitions. `npm run check` passes app/server typechecking, 532 unit tests and one Foundry test. Static build and changed-file ESLint pass.

Visual captures at 390×844, 360×640 and 1440×900 show no horizontal overflow, the header at y=0, and content gutters at x=20 on phones / x=160 on laptop. Captures are local in `scripts/dev/pata-route-reveal-*.png`. A preview-harness MIME fix was needed for exported Next route `.txt` files; no hosting configuration changed. Inspected page content has no viewport-fixed descendants affected by the temporary transform; the home intro uses a top-layer native dialog. Physical-phone/mobile-data and funded setup/approval checks were not rerun for this visual change. Work stays on `frontend-jeston`; PR targets `p1`. No deployment.
