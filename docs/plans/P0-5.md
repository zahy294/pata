**Goal:** device root to household account and encryption key; session key to grant label, owner and encryption key; authenticated encryption and device storage. RPC is the separate P0-5-rpc part.

**Files:** `src/lib/seal/{index.ts,seal.test.ts}`, `src/lib/keys/{index.ts,keys.test.ts,store.ts,store.test.ts,store.browser.spec.ts,store.playwright.config.ts}`, this plan and the blockchain role's completion checklist.

**Tests first (public boundaries confirmed by the user):**

- Seal/open bytes and JSON: round trip, versioned wire format, fresh IV, wrong-key and tampering rejection.
- Key functions: 32-byte randomness, deterministic identities with frozen independent vectors, distinct purposes, non-extractable AES-GCM keys.
- Store save/load: missing values, persistence and replacement, and safe behavior without IndexedDB. Exercise real IndexedDB in a browser where available; no new package.
- Work one failing test and minimal implementation at a time.

Account scalar reduction is `(HKDF integer % (n - 1)) + 1`, as required by this prompt; label encoding uses the first 40 derived bits, RFC 4648 base32, most significant bits first. Existing HKDF strings remain unchanged. Device storage errors must reject rather than silently lose the household root. Passkey ceremonies and RPC are outside this part. All work stays on `blockchain` and pushes to that branch, per the user's instruction.

**Result:** keys, seal and storage implemented on `blockchain`; passkey ceremonies and RPC remain their own prompts.

- AES-GCM-256 envelope, fresh IV, JSON/byte round trips, version/length validation, wrong-key and tamper rejection. Keys of other sizes are rejected.
- HKDF purpose separation and non-extractable AES-GCM keys; root and session inputs must be 32 bytes. Existing HKDF strings unchanged.
- Frozen vectors independently calculated with Node/OpenSSL `hkdfSync` and `createECDH`, with Keccak for Ethereum addresses: root bytes 0..31 -> `0x40F858Eb280b77fA59c94D55ff0709424879A8f5`; session bytes 255..224 -> label `cjx4kqrx`, owner `0xd1052a92D3d7ED17C0e893aC56D9Dfce661687D9`.
- IndexedDB database `pata` v1, object store `household`, separate `device-root` and `household-state` entries. Writes finish only after transaction commit; unavailable storage loads null and rejects writes. Connections close after each operation. No session keys stored.
- Validation: `npm run check` (app + Worker typechecks, 31 unit tests passed, 20 unrelated TODOs, 1 Foundry test passed). The 18 keys/seal/storage unit tests are complete.
- Five real IndexedDB browser tests passed in desktop Chrome: empty device, reload/replacement of roots and state, root length validation, and rollback after abort. Run separately with `npx playwright test --config src/lib/keys/store.playwright.config.ts` (installed Chrome required), keeping browsers outside the fast gate. This does not establish persistence on the demo phones.
- Environment only: `npm ci`, initialized the pinned forge-std submodule, verified the official Foundry 1.8.7 archive checksum and extracted it under ignored `node_modules/.bin`. Foundry checks need the unrestricted execution environment on this machine to find the home/compiler cache. No pinned versions or package dependencies changed, no secrets read, no chain writes or Arkiv interaction.
