# P1: phone-first Pata intro

- **Goal:** a phone-first welcome led by a normal cream Pata wordmark opens like a doorway into the existing home screen.
- **Files:** HomeIntro React component and scoped CSS, home-page wrapper, browser tests, and a scoped Hue design model in docs/design.
- **Direction:** user approved green/gold/cream, tap-to-enter doorway motion, the bottom-right app icon as the app logo and wordmark-only intro. Latest steering removes chrome entirely: normal cream serif lettering. Research Watermelon and Skiper patterns for suitable touch-first components. No animation packages or third-party runtime requests.
- **Tests first:** user confirmed browser seams: enter/keyboard access, reduced motion, once-per-session, storage failure recovery and direct courier-link bypass. One red/green slice at a time. Inspect mobile/desktop, short screens, focus and overflow.
- **Research read:** AGENTS.md, frontend role, P1 branching, Next static/PWA and Playwright research; Hue skill, hero-stage and the reference's public first panel/caption. Exact video motion was unavailable; this is the approved Pata interpretation.
- **Risks:** keep the intro on `/` only, never ahead of courier links or setup. A blocked sessionStorage must not strand entry. Native dialog protects focus; Escape and reduced motion must dismiss immediately. A transition completion fallback prevents animation from trapping the app. No server or chain changes; branch remains frontend-jeston and PR targets p1.
- **Result:** normal cream Pata wordmark, quiet doorway frame and tap-to-enter split-door transition implemented on home only. No chrome/shiny component ships. The separate app logo is the rounded landscape icon, with SVG header/favicon and 192/512 PNG install icons. Session recall is best effort; blocked storage, Escape and reduced motion cannot trap entry. Native dialog isolates keyboard focus and entry moves focus to the existing home heading.

Production previews passed at 414×896, 360×640 and 1440×900; the enter control stays visible without horizontal overflow. Namespaced CSS works with the repo's Tailwind/Turbopack loader, which strips CSS Module export maps; a browser regression verifies the full-screen layout and oversized type. Scoped Hue tokens are in docs/design/pata-intro.yaml and component research is in docs/research/frontend-intro-components.md. No third-party runtime requests or new dependencies.

Validation: 24 intro/loader browser checks passed across phone/desktop, `npm run check` passes 532 unit tests plus one Foundry test and app/server typechecking, static export passes, and new components/test files pass ESLint. The wider page lint run reports four pre-existing effect-state errors in setup/approve/courier; their flow logic was not changed. Existing signed-out home and invalid courier-link handling were re-tested; funded setup/approval were not re-run for these UI-only changes.
