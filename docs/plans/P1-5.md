# P1-5: requester names, the demo seller, hand-off and grant proof

- **Goal:** a requester has its own ENS name with ENSIP-26 records. The consent screen shows what that name says, the courier link goes to the page the name lists, and whoever holds a link can prove it without revealing the address.
- **Decision:** [ADR 0013](../adr/0013-requester-hand-off-through-the-fragment.md). The hand-off goes through the endpoint's `#`, never a request body.
- **Read first:** `ens-v2.md` §8 (ENSIP-26), ADRs 0002, 0004 and 0006, the P0-8 plan (household names).

## Built

- **ENS** (`src/lib/ens/household.ts`):
  - `deployRequesterContracts` shares the household's factory deploys and writes `agent-context` and `agent-endpoint[web]` at deploy.
  - `setRequesterRecords` rewrites both records.
  - `isSafeRequesterEndpoint` checks the endpoint.
  - `readRequesterRecords` is in `lookup.ts`.
- **Consent side** (`src/lib/flows/requester.ts`):
  - `checkRequester`: verified, with its description and endpoint host; unverified; or a plain error.
  - `handOffUrl`.
- **Seller side** (`src/lib/flows/seller.ts`):
  - `setUpSeller`: its own key, gas from the relay, contracts, `/register`, then a check that the records resolve.
  - `addressRequestUrl`, `receiveCourierLink`, `proveGrantHolder`, `verifyGrantProof`.
- **Screens:** `/seller`, labelled a mock. The consent screen's requester card and its "Send link to …" button. A home link to the seller.

No server change: the seller registers through the same `/topup` and `/register` as a household.

## Seams tested

- The ENS deploy and record writes (calldata decoded), and the requester record read.
- `checkRequester` and `handOffUrl`.
- `setUpSeller`, with the server, ENS and storage mocked.
- Proof and verification, with real keys and signatures and a mocked registry read.
- Seller storage, against real IndexedDB.

## Edge cases handled

| Case                                                                                | Handling                                                                                   |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Unsafe endpoint: `http:` off localhost, `javascript:`, credentials, an existing `#` | Refused at deploy; the consent screen keeps the description but offers no hand-off         |
| A request claims a name it doesn't own                                              | The screen shows that name's own records, and the hand-off can only go to that name's page |
| A name with no `agent-context`, or not a valid name                                 | "Doesn't say who it is" warning                                                            |
| The requester's records can't be read                                               | Plain error with Retry; approval still possible                                            |
| Seller name already registered to someone else, or reserved                         | "That name is taken" before any gas is spent                                               |
| Seller name already registered to this seller's key                                 | Setup carries on without registering again                                                 |
| Resolver (address set by the key alone) holds an earlier name's records             | Records rewritten, then checked again                                                      |
| Setup interrupted                                                                   | Every step is safe to repeat; the name is locked until the first one finishes              |
| The seller's key                                                                    | Its own random root (`seller-root`), never the household's                                 |
| Proof after the grant ended or was revoked                                          | "This grant has ended"                                                                     |
| Proof message edited, or signed by another key                                      | "Not the holder"                                                                           |
| Received link in the address bar                                                    | Read once, kept in `sessionStorage`, and the `#` cleared                                   |

## Result

Live chains, localhost, 2026-11-07, one phone-sized browser:

1. The seller set itself up in 55 s, as `dbg-chai-9vy.pata.eth`.
2. "Confirm address with Pata" opened the consent screen. "✓ Checked on its public name" showed the seller's own description and "the link goes to localhost:3000" after 5 s.
3. Approval took 29 s. "Send link to Dbg Chai 9vy" landed on `/seller/`, where the `#` was cleared and "✓ Door link received" showed.
4. "Prove we hold it" passed in 4 s. After the household stopped access, the same check said "This grant has ended".

## Not done

- The live endpoint is whatever origin the seller was set up on. Set up the stage seller on the live site, not on localhost.
- The seller's address request is a link in the same browser. A real shop would send it over WhatsApp.
