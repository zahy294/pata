# P1: morphing location loader

- **Goal:** replace ordinary loading spinners across the app, including green buttons, with a compact morphing indicator that uses the supplied location pin instead of a heart.
- **Files:** shared web MorphLoader and namespaced CSS, local pin asset, existing frontend loading states, browser tests and research note.
- **Tests first:** user confirmed browser seams: observable shape cycle and location icon, still reduced-motion state, real green loading button with unchanged pending text and disabled behavior. Test external network/storage/time boundaries; no private helper tests.
- **Research read:** Hue, frontend role, P1 rules, Playwright and frontend-intro-components.md. The native snippet supplies usage but no implementation; create a lightweight web equivalent with the same requested shapes and no native dependencies.
- **Risks:** 120px is appropriate for a showcase, not a button; use 20–24px in controls and retain loading text. Pause on hidden tabs, respect reduced motion and avoid live-announcing each shape. The location PNG is user-supplied; preserve it locally and tint its alpha mask to the existing foreground color. Recording pulses indicate recording, not loading, and remain intact.
- **Result:** shared web MorphLoader implemented and eight ordinary spinners replaced in home/setup/approve/lookup/courier. Added the same indicator to map placeholders, manual neighbourhood search, name availability and the private-RPC check button. Recording indicators and progress checkpoints retain their original meaning. Existing pending text and disabled buttons remain intact.

The requested nine-stage cycle uses local 64-point shape interpolation and the supplied location PNG's alpha mask in place of a heart. User asset is preserved at public/icons/loading-location.png. Controls use 20px, panels 24px and the map placeholder 28px; callers can set size/color/shapes. Reduced motion shows a still location pin, hidden tabs pause cycling, and decorative shape changes are not announced to assistive technology. This is an authored web counterpart, not a claim to have the missing native component source.

Validation: the real lookup button was exercised with external network requests held pending; tests verify the visible shape change, exact local pin mask, still reduced-motion state, loading text and disabled state. Combined intro/loader suite: 24 phone/desktop passes. `npm run check`, static export and new-component ESLint pass; existing page lint limitations are recorded in P1-intro.md. Production screenshot: scripts/dev/pata-loader-location.png. Source research and candidate component trade-offs are in docs/research/frontend-intro-components.md. No dependency was added and no live chain write was sent.
