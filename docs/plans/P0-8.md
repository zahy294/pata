**Result:** blockchain flow implementation complete. `signIn` loads or durably saves the device root before deriving keys. Web Locks serialize browser tabs; an in-realm queue also serializes concurrent calls and recovers after a failure. Browser setup requires Web Locks support and device storage. `createHousehold` runs both relay top-ups, deploys resolver/grant registry with locality initialized, requests registration, confirms its receipt, verifies the exact owner and both locality text records through the configured Universal Resolver, seals the complete HomeRecord with locally encoded DIGIPIN, and saves HouseholdState. Invalid names/locality and oversized sealed homes fail before funding. No shared types, server, AI/ML or frontend implementations changed.

**Retries:** an address-scoped IndexedDB journal stores the original home only as AES-GCM ciphertext, public results and transaction hashes. Retry with the original input and household keys. Completed stages are reused, known funding/registration hashes are rechecked, a confirmed reverted registration may be requested again, and resolution is checked up to five times with a one-second pause between checks (RPC request time is additional). A failed resolution or final local save does not repeat paid writes. Concurrent setup calls are serialized. The journal is retained after completion to prevent duplicate creates.

**Retry limit:** an interrupted deployment, create or relay request with no durably recorded result leaves a pending marker. It deliberately requires transaction verification before another write; automatic reconciliation of unknown outcomes, partial factory deployments and journal repair are not implemented. An error before broadcast can also leave this conservative marker. Do not clear it blindly: chain ops must first establish whether funding/contracts/registration/entities exist. This is duplicate-write protection, not a claim that every network failure automatically resumes.

**Frontend handoff:** call `await signIn()`, then `await createHousehold(keys, input, onProgress)`. The optional callback receives `SetupStep`: `topup-sepolia`, `topup-arkiv`, `deploy`, `register`, `resolve`, `home-record`, `save`, `complete`. The promise returns the saved HouseholdState. Completed stages are skipped on retries, so a resumed call may emit only remaining stages. Retain the original setup details for retry; do not replace the device root or modify the input to get past a pending marker. Show a generic safe error and distinguish a transaction-verification stop from a normal retry. Voice keys/directions must come from AI/ML's real generation flow; this function does not generate or re-upload clips.
