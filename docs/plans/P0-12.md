# P0-12: revoke and owner index

- **Goal:** revoke ends registry access, removes the payload and records a sealed readonly revoked history entry; retries finish interrupted cleanup.
- **Files:** ENS unregister, Arkiv delete/history/index listing, revoke flow and tests; household storage if a durable cleanup checkpoint is required.
- **Tests first:** confirmed public seams; ended grants send no unregister transaction, expiry races, successful and interrupted cleanup, owned encrypted index listings and metadata-only safe errors.
- **Research read:** AGENTS.md, blockchain role, tickets, glossary, plan courier/revoke sections, ADRs 0002/0005/0008, ENS-v2 and Arkiv research.
- **Risks:** cross-chain operations cannot be atomic. Recheck registry before every unregister; reconcile delete/history after lost acknowledgements. Owner index discovery must check registry liveness, not resolver success. Frontend owns access-screen invocation and courier polling; do not edit its files.
- **Result:** status-first unregister handles a decoded LabelExpired race, missing-record deletion is idempotent, readonly history creation reconciles an exact decrypted match, and paginated owned index discovery verifies each grant against registry ownership. `listLiveGrants(keys, householdName?)` accepts an explicit name or loads device household state. RPC failures never turn into an empty live list.

Revoke persists a household-sealed intent before sending, unregisters first, then deletes the payload and writes history. A retry resumes the same entry after uncertain receipts, deletion or history failures; no permanent pending block exists. Completed checkpoints make repeated clicks harmless; Web Locks serialize tabs where supported, with an in-page promise fallback. IndexedDB must work before any transaction is sent. A checkpoint records the household's revoke intent; an uncertain send followed by natural expiry is still reconciled as that requested revocation, not claimed as proof of its exact chain cause.

An isolated local Chrome run verified the actual IndexedDB checkpoint save/load round trip, including Uint8Array preservation. Unit tests cover unavailable storage, concurrent calls, registry/ancestor independence and retry after a lost ENS acknowledgement or Arkiv outage. Transport retry behavior is recorded in arkiv/friction.md.
