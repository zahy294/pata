# Ticket plans

Before coding a ticket, write `docs/plans/<ticket id>.md` (for example `P0-4.md`) and commit it first. When one ticket is split between people, add the part: `P0-7-map.md`, `P0-7-ai.md`. ETHGlobal wants planning files in the repo, and the commit history is judged.

Keep each plan short:

- **Goal:** the ticket's "done when" from docs/tickets.md, in one line.
- **Files:** what you'll create or change.
- **Tests first:** the failing tests you'll write (TDD), one line each.
- **Research read:** the docs/research notes you read.
- **Risks:** what could block you, and the fallback.
- **Result:** filled in when done: what works, what was cut, anything for arkiv/friction.md.
